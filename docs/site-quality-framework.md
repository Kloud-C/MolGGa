# molgga 사이트 품질 프레임

이 문서는 사이트 변경 전 살펴볼 기준과 변경 후 확인할 항목을 한곳에서 안내합니다. 화면을 고칠 때는 [UI 가이드](ui-guidelines.md), 랭킹·배포·분석 연동은 저장소 [README](../README.md), 이미지 에셋은 [`image/README.md`](../image/README.md)와 해당 폴더의 README를 함께 확인합니다.

## 우선순위

- **P1 — 차단 또는 보호:** 데이터 손실·잘못된 결과, 개인정보 노출, 보안 문제, 주요 경로·서비스 장애. 우회 동작을 만들지 말고 영향 범위를 먼저 좁힙니다.
- **P2 — 주요 기능과 탐색:** 테스트 완료·결과·공유·랭킹, 검색 노출, 언어별 페이지 구조처럼 사용자의 핵심 흐름을 깨뜨리거나 검색·신뢰를 크게 낮추는 문제.
- **P3 — 다듬기와 반복 방지:** 문구 중복, 카드·메타데이터 일관성, 접근성·반응형 세부, 가이드와 자동 점검의 빈틈. P1/P2와 충돌하지 않는 범위에서 정리합니다.

등급은 문제의 원인이 아니라 사용자 영향으로 정합니다. 작은 화면에서 주요 버튼이 잘려 게임을 못 하면 P1/P2가 될 수 있고, 제목 간격 같은 표시 차이는 대체로 P3입니다. 발견한 문제는 `문제 → 영향 → 수정 → 확인` 순서로 기록합니다.

## 변경 전 확인

1. 요청이 분석만인지, 파일 수정까지인지, 커밋·푸시·배포까지인지 구분합니다. 명시되지 않은 외부 변경은 실행하지 않습니다.
2. `git status`와 변경 diff를 살펴 이미 있는 작업을 보존합니다.
3. 이번 변경에 적용되는 문서를 읽습니다.
   - 페이지·문구·컴포넌트: 이 문서와 [UI 가이드](ui-guidelines.md)
   - DB·API·배포·측정: [README](../README.md)와 `functions/`, `migrations/`
   - 결과·카드·월드컵 이미지: [`image/README.md`](../image/README.md), `image/past-life/README.md` 등 실제 에셋 폴더 안내
   - 통합 점검 범위: `scripts/audit-integrations.mjs`
4. 기존 페이지와 공통 코드의 패턴을 확인하고, 변경할 페이지와 언어를 먼저 정합니다.

## 제품 문구와 화면 기준

- 한국어 원문을 먼저 다듬고 `ko.json`, `en.json`, `ja.json`, `zh.json`을 같은 의미로 맞춥니다. 보이는 문자열은 `data-i18n`, 메타데이터 속성은 `data-i18n-attr`로 연결하고 새 문구에는 의미 있는 namespaced 키를 사용합니다. 새 번역이 빠져 키 이름이나 예상치 못한 한국어가 노출되지 않는지 확인합니다.
- 메인 카드와 페이지 도입부는 사용자의 궁금증이나 선택을 앞세웁니다. 문항 수·메뉴 수·라운드 수를 홍보 문장에 반복하지 않습니다. 진행에 필요한 숫자는 선택 버튼, 진행 표시, 상세 안내처럼 필요한 위치에 둡니다.
- 같은 설명이 메인·FAQ·소개 페이지에 길게 반복되지 않게 합니다. 메인에는 발견과 진입을, 접이식 설명에는 짧은 신뢰·개인정보 안내를, 소개 페이지에는 자세한 기준을 둡니다.
- 홈에는 현재 레지스트리의 콘텐츠 카드를 표시하고, 두 개의 접이식 안내(제작 방식, FAQ)를 유지합니다. 접이식 안내는 기본 닫힘 상태여야 하며, 새 콘텐츠의 페이지 경로와 카드 목적지가 모든 언어에서 맞아야 합니다.
- 결과 화면의 이미지·유형명·한줄 소개·설명은 같은 주제를 다뤄야 합니다. 결과를 진단이나 확정적 판단처럼 표현하지 않습니다.

## 콘텐츠 메타데이터와 결과 산정

- 공통 콘텐츠 목록은 `assets/js/content-registry.js`에서 관리합니다. `id`는 변경하지 않는 영문 슬러그로 두고, `type`·`categoryIds`·`tagIds`·번역 키·공개 페이지·썸네일·콘텐츠 정의 소스·화면에 쓸 수치(`metrics`)를 한 항목에 연결합니다. 이미 쓰는 같은 문구의 번역 키를 우선 재사용하고, 새 콘텐츠 전용 문구는 `content.<id>.*`처럼 namespaced 키를 씁니다.
- `metrics`는 화면 문구를 복사해 적는 곳이 아니라 실제 문항 데이터·월드컵 설정에서 검증하는 요약값입니다. 월드컵 후보 수·지원 대진, 테스트 문항·선택지·결과 수가 원본과 다르면 통합 점검이 실패하도록 유지합니다. 콘텐츠에 없는 생성일이나 인기 수치를 임의로 만들어 넣지 않습니다.
- 홈 탐색은 레지스트리에서 제목·설명·분류·태그·진행 정보·썸네일·페이지 경로를 읽습니다. 레지스트리에 정의한 분류를 사용하고, 홈 HTML에 분류 목록을 별도로 하드코딩하지 않습니다. 검색은 현지화된 제목·설명·분류·태그를 대상으로 하며, 모든 태그 ID는 네 언어 사전에서 검색용 이름을 가져야 합니다. 정렬에 쓸 신뢰할 데이터가 없으면 최신순·인기순을 꾸며내지 않습니다.
- 홈의 시작 링크는 공통 미리보기로 이어집니다. 미리보기 숫자는 `metrics`에서 읽되, 월드컵 후보 수와 가능한 대진 크기가 원본 데이터와 일치하는지 통합 점검합니다. 시작 전에 보여줄 정보는 간결하게 유지하며 문항 수를 홍보용 도입 문장에 반복하지 않습니다.
- 카드 보기 방식(기본·간결·목록)은 반응형으로 제공하고 `localStorage`에는 보기 선호만 저장합니다. 답변·결과·개인정보를 저장하지 않습니다. 키보드 포커스, 선택 상태, 좁은 모바일 화면의 레이아웃과 터치 영역을 확인합니다.
- 결과 후 추천은 현재 콘텐츠를 제외하고 `categoryIds`와 `tagIds`의 겹침으로 순위를 정합니다. 콘텐츠 ID를 결과 페이지마다 직접 나열하지 않고, 번역된 제목·설명과 로컬 경로를 레지스트리에서 가져옵니다.
- 채점 원본(HTML, `*-data.js`, `app.js`)과 월드컵 프런트엔드·서버 허용 목록은 별도로 유지합니다. 새 콘텐츠 추가 시 먼저 레지스트리 항목과 네 언어의 번역을 작성하고, 이번 단계에서 지원하지 않는 `source.kind`를 임의로 재사용하지 않습니다.
- 홈 카드 목적지는 레지스트리 페이지와 연결되고, 언어별 홈 카드의 콘텐츠 집합과 순서는 같아야 합니다. 카드 수를 영구 상수로 두지 않고 레지스트리 항목 수와 비교합니다.
- 결과 점수 규칙을 수정하면 `node scripts/audit-result-distributions.mjs`도 실행합니다. 가능한 모든 조합을 전수 조사할 수 있는 콘텐츠는 exact로 표시하고, 전생 테스트처럼 큰 조합은 고정 난수 표본으로 표시합니다. 표본에서 안 나온 결과를 도달 불가라고 단정하지 않습니다. 도달 불가 판정은 전수조사 또는 점수 상한 증명이 있을 때만 보고하고, 출현율을 억지로 균일하게 맞추지 않습니다.

## 구현과 검증 기준

- 공통 UI를 먼저 재사용하고, 구조를 바꿀 때는 `ko/`에 적용한 뒤 나머지 언어의 순서·동작·접근성도 맞춥니다.
- SEO 수정은 canonical, hreflang, Open Graph URL, 사이트맵, 공개 경로, 공유 링크를 함께 확인합니다. 언어별 title·description은 해당 언어로 작성합니다.
- CSS/JS 변경 시 이를 불러오는 모든 HTML 페이지의 버전 토큰을 확인합니다.
- 다국어 변경은 i18next CDN 순서, 루트 JSON 리소스의 키, 각 페이지의 `data-i18n`, 언어 변경 후 `<html lang>`·SEO 메타데이터·canonical·hreflang 경로를 함께 확인합니다. 현재 지원하지 않는 언어는 번역 검토가 끝나기 전 선택기에 추가하지 않습니다.
- 월드컵은 화면 데이터와 서버 허용 목록, DB 스키마, 랭킹 집계를 같이 봅니다. 완료 결과만 기록하고 개별 선택·개인정보를 전송하지 않습니다. 프로덕션에 가짜 투표를 넣지 않습니다.
- 이미지 경로·파일명·라이선스·대체 텍스트를 확인하고, 교체할 때는 캐시 토큰과 이미지 안내 파일을 갱신합니다.
- 콘텐츠·결과 산정·SEO·API·이미지 경로를 바꿨다면 저장소 루트에서 `node scripts/audit-integrations.mjs`, `node scripts/audit-result-distributions.mjs`, `git diff --check`를 실행합니다. UI 변경은 좁은 휴대전화, 일반 휴대전화, 태블릿, 데스크톱 폭에서 넘침·잘림·버튼 터치 영역을 확인합니다.
- 확인 결과와 외부에서만 할 수 있는 후속 작업(예: Cloudflare WAF 설정)은 분리해 보고합니다. 커밋·푸시는 요청받았을 때만 진행합니다.

## 현재 P3 정리

- 메인 카드 아래에 있던 소개성 배너가 히어로와 소개 링크의 내용을 반복해 제거했습니다.
- 접이식 제작 안내에서 FAQ와 소개 페이지가 반복하던 결과 해석 카드를 덜어내고, 직접 작성·브라우저 내 답변 처리·개선 의견 안내를 남겼습니다.
- 영어·일본어·중국어 홈에서 MBTI 카드 설명과 일부 스크린 리더용 카드 이름 번역이 빠진 것을 채웠습니다. 홈의 문구와 접근성 레이블이 번역 사전에 없는 경우 통합 점검이 잡도록 했습니다.
- 공통 번역 스크립트 수정 뒤 일부 페이지가 이전 캐시를 계속 쓸 수 있던 문제를 고쳤습니다. 모든 페이지에 같은 버전 토큰이 있는지 점검합니다.
- 자동 점검에 메인 카드 여덟 개의 언어 간 순서·경로 일치, 야식 월드컵 카드 존재, 두 접이식 안내의 기본 닫힘 상태를 추가했습니다.
- 다음 단계에서 실제 방문·검색 데이터가 생기기 전에는 최신순·인기순 정렬을 추가하지 않습니다. 카드에 보이는 예상 시간과 문항 정보는 탐색·미리보기 용도로 레지스트리 값에서 표시합니다.
