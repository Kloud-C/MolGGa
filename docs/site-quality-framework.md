# molgga 사이트 품질 프레임

이 문서는 사이트 변경 전 살펴볼 기준과 변경 후 확인할 항목을 한곳에서 안내합니다. 화면을 고칠 때는 [UI 가이드](ui-guidelines.md), 랭킹·배포·분석 연동은 저장소 [README](../README.md), 이미지 에셋은 [`image/README.md`](../image/README.md)와 해당 폴더의 README를 함께 확인합니다.

## 우선순위

- **P1 — 차단 또는 보호:** 데이터 손실·잘못된 결과, 개인정보 노출, 보안 문제, 주요 경로·서비스 장애. 우회 동작을 만들지 말고 영향 범위를 먼저 좁힙니다.
- **P2 — 주요 기능과 탐색:** 테스트 완료·결과·공유·랭킹, 검색 노출, 언어별 페이지 구조처럼 사용자의 핵심 흐름을 깨뜨리거나 검색·신뢰를 크게 낮추는 문제.
- **P3 — 다듬기와 반복 방지:** 문구 중복, 카드·메타데이터 일관성, 접근성·반응형 세부, 가이드와 자동 점검의 빈틈. P1/P2와 충돌하지 않는 범위에서 정리합니다.

등급은 문제의 원인이 아니라 사용자 영향으로 정합니다. 작은 화면에서 주요 버튼이 잘려 게임을 못 하면 P1/P2가 될 수 있고, 제목 간격 같은 표시 차이는 대체로 P3입니다. 발견한 문제는 `문제 → 영향 → 수정 → 확인` 순서로 기록합니다.

## 변경 전 확인

1. 요청이 분석만인지, 파일 수정까지인지, 커밋·푸시·배포까지인지 구분합니다. 명시되지 않은 외부 변경은 실행하지 않습니다.
2. `git status`와 변경 diff를 살펴 이미 있는 작업을 보존합니다.
3. 이번 변경에 적용되는 문서를 읽습니다.
   - 페이지·문구·컴포넌트: 이 문서와 [UI 가이드](ui-guidelines.md)
   - DB·API·배포·측정: [README](../README.md)와 `functions/`, `migrations/`
   - 결과·카드·월드컵 이미지: [`image/README.md`](../image/README.md), `image/past-life/README.md` 등 실제 에셋 폴더 안내
   - 통합 점검 범위: `scripts/audit-integrations.mjs`
4. 기존 페이지와 공통 코드의 패턴을 확인하고, 변경할 페이지와 언어를 먼저 정합니다.

## 제품 문구와 화면 기준

- 한국어 원문을 먼저 다듬고 `ko.json`, `en.json`, `ja.json`, `zh.json`을 같은 의미로 맞춥니다. 보이는 문자열은 `data-i18n`, 메타데이터 속성은 `data-i18n-attr`로 연결하고 새 문구에는 의미 있는 namespaced 키를 사용합니다. 새 번역이 빠져 키 이름이나 예상치 못한 한국어가 노출되지 않는지 확인합니다. 링크를 문장 중간에 넣을 때는 링크 앞뒤 번역 조각의 공백과 문장부호까지 합친 문장으로 검토합니다.
- 메인 카드와 페이지 도입부는 사용자의 궁금증이나 선택을 앞세웁니다. 문항 수·메뉴 수·라운드 수를 홍보 문장에 반복하지 않습니다. 진행에 필요한 숫자는 선택 버튼, 진행 표시, 상세 안내처럼 필요한 위치에 둡니다.
- 같은 설명이 메인·FAQ·소개 페이지에 길게 반복되지 않게 합니다. 메인에는 발견과 진입을, 접이식 설명에는 짧은 신뢰·개인정보 안내를, 소개 페이지에는 자세한 기준을 둡니다.
- 홈에는 현재 레지스트리의 콘텐츠 카드를 표시하고, 두 개의 접이식 안내(제작 방식, FAQ)를 유지합니다. 접이식 안내는 기본 닫힘 상태여야 하며, 새 콘텐츠의 페이지 경로와 카드 목적지가 모든 언어에서 맞아야 합니다.
- 결과 화면의 이미지·유형명·한줄 소개·설명은 같은 주제를 다뤄야 합니다. 결과를 진단이나 확정적 판단처럼 표현하지 않습니다.
- 유형 결과의 상단 설명은 문장마다 글머리표 목록으로 보여줍니다. 아래 상세 정보·궁합 카드에는 글머리표를 넣지 않고 작은 제목과 본문을 같은 구조로 배치합니다. 공유용 설명은 기호 없는 자연스러운 문단으로 관리합니다. 화면 문구를 수정하면 별도 필드인 공유 문구도 함께 검토·수정하고, 두 문구의 네 언어 번역을 맞춥니다. 테스트 이름과 결과를 공유 제목에 함께 쓸 때 결과명은 대괄호로 감쌉니다.

## 콘텐츠 기준선과 재검토 범위

- 완료한 전체 콘텐츠 점검의 범위와 결과는 [콘텐츠 감사 기준선](content-audit-baseline.md)에 기록합니다. 기준선에 등록된 기존 콘텐츠는 기본적으로 동결된 것으로 봅니다.
- 사용자가 특정 콘텐츠의 검토·수정·번역을 직접 요청하지 않은 동안, 기존 콘텐츠 문구·문항·결과 연결을 다시 읽거나 고쳐 쓰지 않습니다. 일반 통합 점검도 변경되지 않은 콘텐츠의 수동 재감수를 요구하지 않습니다.
- 콘텐츠나 관련 동작을 바꾸는 요청이 오면 해당 콘텐츠 ID와 직접 연결된 질문·선택지·결과·공유 문구·카드·메타데이터·번역만 검토합니다. 나머지 기준선 항목은 그대로 둡니다. 새 콘텐츠는 전체 검토 후 기준선에 항목과 결과를 추가합니다.
- 점수·가중치·결과 연결을 바꿀 때만 `node scripts/audit-result-distributions.mjs`를 실행합니다. 문구·번역만 바꾼 경우에는 결과 분포를 다시 계산하지 않습니다. 레지스트리·데이터·페이지·번역 구조 변경에 필요한 통합 감사와 표적 확인은 계속 수행합니다.
- 동결된 콘텐츠에서 문제를 발견해도 별도 요청 없이 원고를 수정하지 않습니다. 문제와 영향을 기록해 사용자가 검토할 수 있게 하고, 수정 요청을 받으면 그 항목만 다시 엽니다.

## 콘텐츠 메타데이터와 결과 산정

- 공통 콘텐츠 목록은 `assets/js/content-registry.js`에서 관리합니다. `id`는 변경하지 않는 영문 슬러그로 두고, `type`·`categoryIds`·`tagIds`·번역 키·공개 페이지·썸네일·콘텐츠 정의 소스·화면에 쓸 수치(`metrics`)·짧은 카드 라벨(`cardLabelKey`)·실제 등록일(`createdAt`)을 한 항목에 연결합니다. 새 콘텐츠 전용 문구에는 `content.<id>.*` 또는 콘텐츠 이름공간처럼 읽기 쉬운 namespaced 키를 씁니다.
- 홈 콘텐츠 카드는 `content-browser.js`가 이 레지스트리에서 자동 생성합니다. 언어별 `index.html`에는 카드 마운트 지점만 두고 개별 카드 HTML을 중복해서 관리하지 않습니다. 검색·분류·진행 정보·미리보기·즐겨찾기·최근 기록·추천·공유 경로도 같은 메타데이터를 사용합니다.
- 최신순 정렬은 레지스트리의 실제 등록일을 사용합니다. 인기순은 미리보기에서 실제 시작을 누른 이벤트의 콘텐츠별 누적 합계를 D1에서 가져오며, 시작 횟수 내림차순과 레지스트리 순서의 안정적인 동률 처리만 사용합니다. NEW 배지는 인기순 순서에 영향을 주지 않습니다. 원시 IP, 쿠키, 장치 ID, 계정, 테스트 답변·결과를 저장하거나 분석 도구에 보내지 않습니다. 이 값은 순 사용자 수나 조작이 불가능한 통계가 아니며, 집계 API는 Cloudflare WAF Rate Limiting으로 보호합니다.
- `metrics`는 화면 문구를 복사해 적는 곳이 아니라 실제 문항 데이터·월드컵 설정에서 검증하는 요약값입니다. 월드컵 후보 수·지원 대진, 테스트 문항·선택지·결과 수가 원본과 다르면 통합 점검이 실패하도록 유지합니다. 콘텐츠에 없는 생성일이나 인기 수치를 임의로 만들어 넣지 않습니다.
- 홈 탐색은 레지스트리에서 제목·설명·분류·태그·진행 정보·썸네일·페이지 경로를 읽습니다. 레지스트리에 정의한 분류를 사용하고, 홈 HTML에 분류 목록을 별도로 하드코딩하지 않습니다. 검색은 현지화된 제목·설명·분류·태그를 대상으로 하며, 모든 태그 ID는 네 언어 사전에서 검색용 이름을 가져야 합니다. 최신순은 실제 등록일, 인기순은 D1의 콘텐츠 시작 누계를 내림차순으로 사용하며 같은 횟수끼리는 레지스트리 순서를 유지합니다. NEW 배지와 추천 표시는 인기순 정렬을 바꾸지 않습니다. 집계 API를 사용할 수 없으면 인기순을 비활성화하고 최신순을 유지합니다.
- 홈의 시작 링크는 공통 미리보기로 이어집니다. 미리보기 숫자는 `metrics`에서 읽되, 월드컵 후보 수와 가능한 대진 크기가 원본 데이터와 일치하는지 통합 점검합니다. 시작 전에 보여줄 정보는 간결하게 유지하며 문항 수를 홍보용 도입 문장에 반복하지 않습니다.
- 카드 보기 방식(기본·간결·목록), 즐겨찾기 콘텐츠 ID, 최근 본 콘텐츠 ID와 마지막 열람 시각은 편의 기능을 위해 `localStorage`에만 저장합니다. 질문 답변·검사 결과·계정 정보는 저장하지 않습니다. 저장 자료를 지울 수 있는 사용자 제어와 개인정보처리방침을 함께 제공하고, 키보드 포커스·선택 상태·좁은 화면의 터치 영역도 확인합니다.
- 결과 후 추천은 현재 콘텐츠를 제외하고 `categoryIds`와 `tagIds`의 겹침으로 순위를 정합니다. 콘텐츠 ID를 결과 페이지마다 직접 나열하지 않고, 번역된 제목·설명과 로컬 경로를 레지스트리에서 가져옵니다.
- 채점 원본(HTML, `*-data.js`, `app.js`)과 월드컵 프런트엔드·서버 허용 목록은 별도로 유지합니다. 새 콘텐츠 추가 시 먼저 레지스트리 항목과 네 언어의 번역을 작성하고, 이번 단계에서 지원하지 않는 `source.kind`를 임의로 재사용하지 않습니다.
- 선택 응답을 여러 결과에 연결하는 아키타입 테스트는 `scores`에 `{ id, weight }`를 사용해 주된 근거와 보조 근거를 구분할 수 있습니다. 여러 결과를 같은 강도로 연결할 의도가 있을 때만 같은 가중치를 줍니다. 문자열 ID 형식은 기존 콘텐츠 호환용이며 1점으로 처리합니다. 동물상 문항의 쉼표 구분 값은 첫 ID를 주된 근거(2점), 뒤 ID를 보조 근거(각 1점)로 사용합니다. 질문 문구와 결과 설명을 확인한 뒤 연결하고, 결과 비율을 평탄하게 만들려고 의미를 희생하지 않습니다.
- 최고 점수가 동점이면 콘텐츠 ID와 전체 답변 패턴을 해시해 안정적으로 하나를 고릅니다. 같은 응답은 언제나 같은 결과를 내며, 질문 순서나 결과 등록 순서가 동점 우선권이 되지 않도록 합니다.
- 홈 카드 목적지는 레지스트리 페이지와 연결되고, 언어별 홈 카드의 콘텐츠 집합과 순서는 같아야 합니다. 카드 수를 영구 상수로 두지 않고 레지스트리 항목 수와 비교합니다.
- 결과 점수 규칙을 수정하면 `node scripts/audit-result-distributions.mjs`도 실행합니다. 가능한 모든 조합을 전수 조사할 수 있는 콘텐츠는 exact로 표시하고, 전생 테스트처럼 큰 조합은 고정 난수 표본으로 표시합니다. 표본에서 안 나온 결과를 도달 불가라고 단정하지 않습니다. 도달 불가 판정은 전수조사 또는 점수 상한 증명이 있을 때만 보고하고, 출현율을 억지로 균일하게 맞추지 않습니다.

## 구현과 검증 기준

- 공통 UI를 먼저 재사용하고, 구조를 바꿀 때는 `ko/`에 적용한 뒤 나머지 언어의 순서·동작·접근성도 맞춥니다.
- SEO 수정은 canonical, hreflang, Open Graph URL, 사이트맵, 공개 경로, 공유 링크를 함께 확인합니다. 언어별 title·description은 해당 언어로 작성합니다.
- CSS/JS 변경 시 이를 불러오는 모든 HTML 페이지의 버전 토큰을 확인합니다.
- 다국어 변경은 i18next CDN 순서, 루트 JSON 리소스의 키, 각 페이지의 `data-i18n`, 언어 변경 후 `<html lang>`·SEO 메타데이터·canonical·hreflang 경로를 함께 확인합니다. 현재 지원하지 않는 언어는 번역 검토가 끝나기 전 선택기에 추가하지 않습니다.
- 월드컵은 화면 데이터와 서버 허용 목록, DB 스키마, 랭킹 집계를 같이 봅니다. 완료 결과만 기록하고 개별 선택·개인정보를 전송하지 않습니다. 프로덕션에 가짜 투표를 넣지 않습니다.
- 이미지 경로·파일명·라이선스·대체 텍스트를 확인하고, 교체할 때는 캐시 토큰과 이미지 안내 파일을 갱신합니다.
- 레지스트리, 콘텐츠 데이터 구조·수치, 페이지 구조, 번역 키 집합, SEO 경로, API 또는 이미지 연결을 바꾸면 `node scripts/audit-integrations.mjs`와 `git diff --check`를 실행합니다. 기존 번역 키의 값만 고친 경우에는 해당 키의 한국어 원문과 네 언어 값만 대조하고 `git diff --check`를 실행합니다. 점수·가중치·결과 연결을 바꾼 경우에만 `node scripts/audit-result-distributions.mjs`를 추가로 실행합니다. UI 변경은 좁은 휴대전화, 일반 휴대전화, 태블릿, 데스크톱 폭에서 넘침·잘림·버튼 터치 영역을 확인합니다.
- 확인 결과와 외부에서만 할 수 있는 후속 작업(예: Cloudflare WAF 설정)은 분리해 보고합니다. 커밋·푸시는 요청받았을 때만 진행합니다.

## 현재 3차 확장

- 홈에서 즐겨찾기 및 최근 본 콘텐츠를 필터링하고, 별표를 눌러 저장하거나 해제할 수 있습니다. 최근 목록은 최대 8개이며 홈에서 삭제할 수 있습니다.
- 최근/즐겨찾기 데이터는 등록된 콘텐츠 ID와 마지막 열람 시각만 기기의 브라우저 `localStorage`에 기록합니다. 서버 전송은 없고, 테스트 답변과 결과는 저장하지 않습니다. 이 동작을 네 언어 개인정보처리방침과 통합 감사에서 확인합니다.
- 광고·분석 또는 저장 방식을 추가·변경할 때 개인정보처리방침에서 데이터, 목적, 업체, 쿠키/로컬 저장소 사용과 선택·거부 경로를 함께 확인합니다. AdSense의 실제 광고 기술 제공업체 목록과 EEA·영국·스위스용 Google 인증 CMP 상태는 저장소 코드만으로 확인할 수 없으므로 게시 전 AdSense Privacy & messaging 및 광고 기술 제공업체 설정에서 확인합니다.
- 콘텐츠 페이지를 직접 열어도 최근 목록에 반영되며, 검색이 결과를 찾지 못하면 검색어 조각이나 선택 분류에 맞는 항목을 제안합니다. 제안은 인기도가 아니라 레지스트리 메타데이터 일치도로 정합니다.
- 생성일 데이터가 없는 콘텐츠에는 NEW를 표시하지 않습니다. 최신순은 레지스트리의 등록일을 이용하고 인기순은 D1의 누적 시작 횟수 내림차순만 사용합니다. NEW 표시는 어떤 콘텐츠 정렬에도 우선순위를 부여하지 않습니다.
- 답변 저장 및 이어하기는 답변을 저장하지 않는 현재 정책과 상충하므로 보류합니다. 추후 진행 저장을 도입하려면 데이터 항목·보존 기간·삭제 방법과 개인정보 안내를 먼저 설계합니다.
